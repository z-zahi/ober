# Ober Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Ober Phase 1: nine working screens in Expo Go on a Supabase-backed (or mock-backed) rider/driver ride loop, four PlantUML diagrams, and the Word report.

**Architecture:** MVVM with a repository layer. Expo Router screens (View) call hooks (ViewModel) that call a `RideRepository` interface backed by Supabase or an in-memory mock. Pure domain rules (fare, status transitions, PIN) live in `src/domain/` and are unit-tested.

**Tech Stack:** Expo SDK 57, Expo Router, NativeWind 4.2.7 + Tailwind 3, React Native Reusables, `@supabase/supabase-js` + `expo-sqlite` localStorage, `react-native-maps`, `expo-location`, Jest via `jest-expo`, PlantUML, docx.

**Spec:** `docs/superpowers/specs/2026-10-26-ober-phase1-design.md`

## Global Constraints

- Package manager is Bun: use `bunx expo install <pkg>` for every runtime package; `bun add -d` only for pure dev tooling (tailwindcss, prettier plugin, jest types).
- Everything must run in Expo Go on SDK 57: no package that needs a development build.
- Routes only in `src/app/`; components, hooks, domain, data outside it. Path alias `@/*` → `./src/*`.
- NativeWind 4.2.7 with Tailwind `^3.4.17`; class names are static strings (no runtime string assembly).
- Money is integer piastres (`*_cents`); fare rule `max(1500 + round(km*600), 2500)`.
- Ride statuses: `requested | accepted | arrived | in_progress | completed | cancelled`.
- Screen IDs S1–S9 and routes exactly as the spec's screen table.
- No `Co-Authored-By` trailer on any commit. Do not commit unless the user asks.
- Report and diagrams: `docs/diagrams/*.puml` + PNG, `docs/report/Ober-Phase-1-Report.docx`.

## Review Focus

1. Two drivers accept the same request at once: the second must see "This request is no longer available", not a silent success (Task 4 mock test; Task 4 SQL `accept_ride`).
2. Driver enters a wrong PIN: trip stays `arrived`, field shows an error, input is kept (Task 4 mock test; Task 7 screen).
3. Rider cancels after the driver started: cancel button is absent and the repository rejects it (Task 3 `canRiderCancel`; Task 4 mock test).
4. Supabase env vars missing: app boots into mock mode with a visible "Demo mode" notice, never a crash (Task 4 selector; Task 5 profile notice).
5. Location permission denied: S1 still renders the map centred on campus with pickers usable (Task 6).
